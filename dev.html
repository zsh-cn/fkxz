环境要求

各组件运行环境与依赖

Python 工具

项目 要求
Python 3.8 及以上
必需依赖 requests、tkinter（标准库）
可选依赖 curl_cffi，用于增强模式；未安装时自动使用标准请求方式
操作系统 Windows、Linux、macOS（拖放文件、任务栏进度仅 Windows）

安装依赖

pip install -r requirements.txt
  • requests：HTTP 请求库（必需）
  • tkinter：图形界面标准库，Linux 环境如缺少需先执行 sudo apt install python3-tk
  • curl_cffi：浏览器模拟库（可选，用于增强模式绕过反爬限制）

网页端

  • 支持 Service Worker 的现代浏览器
  • 站点需使用 HTTPS 或 localhost 访问，且脚本与页面同源
  • 分片所在服务器需允许跨域访问，否则浏览器会拦截请求

使用方式

多种使用方式，满足不同场景需求

聚合 GUI 工具

聚合程序（分块 + 下载）

python main.py

启动后左侧边栏显示“文件分块”和“文件下载”两个功能入口，点击侧边栏按钮即可切换，无需开启多个窗口。两个功能在切换后保留原有状态，关闭主窗口时统一结束进行中的任务。

独立 GUI 工具

分块文件

python wjfk.py

选择或拖入源文件，确认输出目录与输出文件名，设置分片大小（1–1024 MB，默认 10 MB）和校验方式后点击“开始分块”。界面会显示源文件大小与预计分片数，并在开始前检查输出目录可用空间。

分块完成后可将 .fk 分片和 .fkx 清单上传到服务器，保持同一目录结构，通过 .fkx 的访问地址分享。

合并文件（本地/远程）

python wjxz.py

在输入框中填入 .fkx 文件的本地路径或完整 URL，程序根据输入类型自动切换模式。解析清单后会显示文件名、文件大小与分片数量。

  • 校验方式：双校验、只校验分片、只校验整文件、不校验四档可选，清单缺少对应校验值时自动降级
  • 增强模式：默认启用，需 curl_cffi；未安装时选项不可用，自动使用标准请求方式
  • 并发与重试：并发数量可调，单个分片失败不影响其余分片，整轮结束后自动重试未完成分片

确认后点击“开始合并”（本地）或“开始下载”（远程）。

网页端方式

使用 Service Worker 下载器

  1. 将 web/index.html 与 web/sw.js 部署到同一静态目录（两者均需 sw.js，不可缺省）
  2. 通过 URL 参数提供 .fkx 文件地址：
    https://your-domain.com/index.html?fkx=https://example.com/file.fkx
  3. 页面自动加载清单并显示文件信息，点击“下载”后由浏览器完成文件保存
  • 要求站点使用 HTTPS 或 localhost，且脚本与页面同源
  • fkx 参数仅接受 http(s) 地址或相对路径
  • 支持浏览器下载管理器暂停与继续，续传由浏览器发起，页面不保存进度
  • 网页端不进行完整性校验，仅按清单长度合并分片

组件说明

各核心组件的功能与特性

聚合 GUI 工具

main.py — 聚合程序

Tkinter 图形界面，集成文件分块与文件下载两大功能，通过侧边栏实现功能切换。

  • 左侧边栏持久化显示“文件分块”和“文件下载”两个功能入口
  • 点击侧边栏按钮即可在两项功能之间切换，无需开启多个窗口
  • 两个功能在切换后保留原有状态，关闭主窗口时统一结束进行中的任务
  • 两个功能各自提供完成关机开关，两个开关互不影响

独立 GUI 工具

wjfk.py — 文件分块

Tkinter 图形界面，将大文件分块为多个 .fk 分片，并生成记录校验值的 .fkx 清单。

  • 支持选择、输入路径或拖入源文件，输出目录留空时保存到程序所在目录并记住上次填写
  • 自定义分片大小（1–1024 MB，默认 10 MB），界面显示源文件大小与预计分片数
  • 校验方式四档可选：双校验、只校验分片、只校验整文件、不校验
  • 开始前检查输出目录可用空间，进度同步映射到 Windows 任务栏
  • 支持取消分块；源文件被修改或截断时清理已生成分片并报错
  • 可选完成后自动打开文件夹，或分块成功后进入 60 秒关机倒计时

wjxz.py — 文件下载

Tkinter 图形界面，读取 .fkx 清单，获取所有分片并合并还原。

  • 本地模式：从本地目录读取 .fkx 和 .fk 文件直接合并
  • 远程模式：从 URL 获取清单，并发下载 .fk 分片（并发数量可调）后合并
  • 输入框兼容远程地址与本地路径，按输入类型自动切换模式；清单文件可拖入窗口
  • 解析清单后显示文件名、文件大小与分片数量，下拉框只保留该清单支持的校验方式
  • 实时进度显示（字节进度条 + 百分比 / 已下载量 / 速度 / 分片计数），进度同步到任务栏
  • 校验方式四档可选，清单缺少对应校验值时自动降级；校验失败删除结果文件并提示
  • 失败重试：单个分片失败不影响其余分片，整轮结束后自动重试未完成的分片
  • 断点续传：分片保留在临时目录，重新下载按大小 + 校验值跳过完整分片，残缺分片用 Range 从断点续传；校验结果缓存后按大小与修改时间复用
  • 合并成功后自动清理临时文件，可选完成后打开文件夹或关机
  • 增强模式（默认启用）：使用 curl_cffi 模拟 Chrome 浏览器请求特征，兼容 Cloudflare 验证、防盗链等访问限制；未安装依赖时选项不可用，自动使用标准请求方式

公共模块

core.py — 分块与合并逻辑

分块切分、清单读写、分片合并与校验等核心逻辑，供各 GUI 程序共用。

utils.py — 公共工具模块

各 GUI 程序共享的底层工具函数。

  • DPI 感知设置与高分屏自适应窗口尺寸
  • SHA-256 流式计算（支持取消与进度回调）
  • 图标路径解析（兼容 PyInstaller 打包环境）与 Tkinter 图标加载
  • 目录/文件选择对话框封装、输入框右键菜单（剪切/复制/粘贴/删除/全选）
  • 统一 GUI 启动入口 run_gui_app

config.py — 全局常量

网络、IO、并发、配色与窗口尺寸等全局常量集中定义。

网页端工具 — web/

sw.js + index.html — Service Worker 下载器

基于 Service Worker 的浏览器端下载器，通过 SW 拦截请求并在浏览器端流式合并分片后返回完整文件。

  • sw.js：Service Worker 脚本，拦截 /fkxz 路径的请求，解析 .fkx 文件获取分片列表，逐个抓取 .fk 分片并通过 ReadableStream 流式合并，最终以单个文件形式返回给浏览器下载
  • index.html：配套前端页面，自动注册 Service Worker，解析 .fkx 文件并展示文件信息，点击下载按钮后通过 SW 代理完成流式合并下载
  • 清单解析只存在于 sw.js：页面通过 postMessage 获取解析结果，规则与桌面端一致（按 chunk_N 编号排序并校验连续性、分片数量与总大小）

Service Worker 方案的优势：

  • 无需 File System Access API，兼容性更好
  • 合并过程在 SW 后台线程完成，不阻塞主线程
  • 直接触发浏览器原生下载行为，用户体验更流畅
  • 页面侧同源，不涉及 CORS；分片服务器仍需返回 Access-Control-Allow-Origin（SW 内的 fetch 默认 cors 模式，并不能绕过跨域）
  • 支持浏览器下载管理器暂停与继续，取消下载会中止后续分片的请求

文件格式

了解 .fkx 清单与 .fk 分片的格式定义

.fkx 清单文件

命名格式：{原文件名}.fkx（如 video.mp4.fkx），内容为纯文本键值对：

filename=video.mp4
chunk_size=10485760
num_chunks=3
chunk_1=video.mp4-1.fk,10485760,<分片1校验值>
chunk_2=video.mp4-2.fk,10485760,<分片2校验值>
chunk_3=video.mp4-3.fk,5242880,<分片3校验值>
total_size=26214400
sha256=<完整文件校验值>
字段 说明
filename 还原后的文件名（必填）
chunk_size 分片大小（字节）
num_chunks 分片数量，须与条目数一致
chunk_N 分片文件名、大小、校验值，编号自 1 起且连续；校验值可省略
total_size 文件总大小（字节），须与各分片大小之和一致
sha256 完整文件校验值，选择不写入整文件校验时该行缺省

清单在解析阶段即校验字段一致性：编号不连续、编号重复、数量或总大小不符会直接报错。

.fk 分片文件

命名格式：{原文件名}-{编号}.fk，编号自 1 起。分片为源文件的连续字节切分，除最后一片外大小一致。

网页端工具

无需安装，浏览器直接使用

Service Worker 下载器

基于 Service Worker 的浏览器端下载器，SW 拦截请求并流式合并分片。

  • 无需 File System Access API，兼容性更好
  • 合并过程不阻塞主线程，直接触发浏览器原生下载
  • 支持浏览器下载管理器暂停与继续，续传由浏览器发起，页面不保存进度
  • 服务器支持断点请求时续传效率更高，不支持时功能仍可用，但会重复传输部分数据
  • 不进行完整性校验，仅按清单长度合并分片
  • 页面与 SW 同源，不涉及 CORS；分片服务器仍需允许跨域访问
  • 取消下载会中止后续分片的请求；页面功能依赖 Service Worker，注册失败时无法下载
# 访问格式
https://your-domain.com/index.html?fkx=https://example.com/file.fkx

要求站点使用 HTTPS 或 localhost（Service Worker 安全策略要求），sw.js 必须与 index.html 同源部署；fkx 参数仅接受 http(s) 地址或相对路径。

PyInstaller 打包说明

如果你想自行从源码打包为 .exe 可执行程序

安装 PyInstaller

pip install pyinstaller

在项目根目录下执行以下命令，打包产物输出至 dist/ 目录：

打包 wjfk.exe（文件分块）

pyinstaller --onefile --windowed --name wjfk --distpath dist --icon icon/wjfk.ico --add-data "icon;icon" wjfk.py
  • --icon icon/wjfk.ico：设置 exe 程序图标
  • 任务栏/窗口图标：icon/wjfk.png（通过 --add-data 打包，程序运行时自动加载）

打包 wjfkxz.exe（聚合程序）

pyinstaller --onefile --windowed --name wjfkxz --distpath dist --icon icon/wjfkxz.ico --add-data "icon;icon" main.py
  • --icon icon/wjfkxz.ico：设置 exe 程序图标
  • --add-data "icon;icon"：打包图标资源（窗口/任务栏图标 icon/wjfkxz.png）

打包 wjxz.exe（文件下载）

pyinstaller --onefile --windowed --name wjxz --distpath dist --icon icon/wjxz.ico --add-data "icon;icon" --hidden-import curl_cffi wjxz.py
  • --icon icon/wjxz.ico：设置 exe 程序图标
  • --hidden-import curl_cffi：显式包含 curl_cffi 模块（增强模式依赖）
  • 任务栏/窗口图标：icon/wjxz.png（通过 --add-data 打包，程序运行时自动加载）

打包说明

  • 打包后的 exe 文件位于 dist/ 目录下
  • 建议在打包前先执行 pip install -r requirements.txt 确保所有依赖已安装
  • 图标目录需随程序一同打包，否则运行时无法加载窗口与任务栏图标
  • 文件下载程序需显式包含 curl_cffi，否则增强模式在打包后不可用
  • 打包产生的 build/ 目录与 .spec 文件可手动删除
